# Completion Runtime 설계

상태: 구현 완료. 현재 API와 자세한 동작은 [반복 실행 문서](Completion-Runtime.md)를 따른다.

## 호출과 책임

`Bridge.run(HubRequest, execute_tool=callback)`으로 모델 호출과 도구 결과 전달을 반복한다.
콜백은 도구 호출 표준의 `name`과 `arguments`만 받는다. 사용자·대화 문맥과 정책은
소비 앱의 클로저에서 참조하고, 실제 도구 실행과 HITL 판정 역시 소비 앱에서 수행한다.

- `await bridge.run(...)`은 최종 `Run`을 반환한다.
- 같은 실행 객체를 비동기 순회하면 기존 `HubResponse` 델타를 계속 받을 수 있다.
- `ToolOutput.result`가 없으면 미해결 HITL 기록을 보존하고 종료한다.
- 모델 응답에 도구 호출이 없으면 완료한다.
- 실행 등록소나 승인 입력·재개 API는 제공하지 않는다.

## 결과와 수명

`Run`은 초기 요청, 입력과 생성 메시지, 요청별 응답, `list[HitlDraft]`를 제공한다.
`HitlDraft`는 콜백의 판정·실행 기록 및 선택적인 모델용 결과와 작업 핸들을 보존한다.
작업 생성과 정책 판정을 라이브러리가 중복 구현하지 않는다.
콜백이 반환한 백그라운드 작업은 메인 종료 후에도 유지하며 소비 앱이 관리한다.
명시적 `Run.aclose()`는 인계받은 작업을 취소하고 기다린다.

별도 런타임 구성 객체, 정책 Protocol, 도구 실행기 Protocol, HitlTask는 사용하지 않는다.
`common-hitl-chat`의 기존 실행 로직을 변경하지 않았으며, 이후 연동은 소비 앱의 콜백
어댑터에서 실제 ToolManager 인터페이스와 실행 기록을 변환해야 한다.

## 검증 기준

1. HubRequest의 모델·메시지·도구·생성 설정·params가 복사되고 후속 요청에도 유지된다.
2. 콜백은 name·arguments만 받으며 클로저로 외부 관리자·정책·문맥을 사용할 수 있다.
3. 해결된 결과로 후속 요청을 수행하고, 미해결 기록 뒤에는 요청이나 나머지 콜백을 진행하지 않는다.
4. 원본 모델 호출 ID·순서를 유지하며 콜백이 제공한 객체를 수정하지 않는다.
5. Task 핸들은 복사·직렬화하지 않고 종료·오류 후에도 결과에서 접근할 수 있다.
6. 델타 순회와 await 소비, 호출 제한, 오류·취소·동시 소비 및 모델 연결 정리를 검증한다.
