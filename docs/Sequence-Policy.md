# seq 좌표 발급 정책

`seq`는 스트림 델타의 블록 식별값이자 표시 순서다. 사람이 읽었을 때 의미와 순서를 이해할 수
있도록 각 변환기가 자신의 응답 구조에 맞게 좌표를 배정한다. 발급 규칙은 변환기가 소유하며,
공통 코드는 마지막 수신 블록을 기준으로 위치를 추론하거나 번호를 발급하지 않는다.

## 1. 논리 좌표는 왼쪽부터 배정한다

논리적으로는 가변 길이 튜플처럼 배정한다. 먼저 비교해야 하는 그룹·위치는 왼쪽에 두고,
그 안의 위치·분류·원소 index를 오른쪽에 둔다. 후속 성분의 의미는 앞선 그룹이나 item 종류에
따라 달라도 된다. 모든 성분을 전역적으로 동일한 의미에 할당하지 않는다.

분류값, API에서 수신한 index, 변환기가 순차 발급하는 출현 번호는 모두 0부터 사용한다.
같은 블록의 후속 델타는 전체 좌표를 재사용한다. 새 독립 블록에만 새 좌표를 배정한다.

## 2. 최대 길이는 변환기별로 고정한다

각 변환기는 필요한 최대 길이를 스트림 처리 전에 정한다. 짧은 논리 좌표는 오른쪽을 `-1`로
채워 그 길이로 정규화한 뒤 출력한다. `normalize_seq(seq, width)`가 이 연산을 제공한다.
현재 수신한 블록들의 최대 길이를 계산해 정규화 길이를 변경해서는 안 된다.

```python
normalize_seq((1, 2), 4)     # (1, 2, -1, -1)
normalize_seq((1, 2, 0), 4)  # (1, 2, 0, -1)
```

`-1`은 좌표 생략 전용 값이다. 실제 분류·위치·순번은 0 이상으로 배정한다. 수신 index에
`+1` 보정을 하지 않는다. 실제 위치를 알 수 없는 정보를 임의의 API index로 간주하지 않고,
변환기가 정한 별도 그룹이나 명시적인 출현 번호를 사용한다.

공통 앞 성분 뒤에서 본체의 `-1`과 하위 항목의 0 이상 값이 처음 다르므로 본체가 먼저다.
오른쪽 패딩은 그보다 왼쪽에서 이미 결정된 순서를 변경하지 않는다. 이 조건을 만족하면
정규화된 서로 다른 논리 좌표가 같은 좌표가 되지 않는다.

## 3. 벤더별 발급 규칙

| 변환기 | 최대 길이 | 규칙 |
|---|---:|---|
| Messages | 1 | `(index,)`. 수신 content block index 그대로 |
| Chat Completions | 2 | `(출현 그룹, 하위 index)`. 연속 채널은 같은 그룹. 일반 채널은 하위 좌표 생략 |
| Responses | 4 | 최상위 그룹과 item 종류에 따라 후속 좌표 해석 |
| GenerateContent | 2 | `(정보 그룹, 그룹 내부 index)`. 콘텐츠는 독립 part의 출현 번호 |

### Messages

각 `tool_use`도 독립 content block이므로 수신 index만 사용한다. 역순으로 수신해도 원본
index가 최종 순서를 결정한다. 인용은 대상 text 블록의 중첩 `citations`로 처리한다.

### Chat Completions

출현 그룹은 0부터 증가한다. 연속한 같은 채널은 같은 그룹을 재사용하고, 채널 전환 시
새 그룹을 배정한다. 도구 호출은 첫 도구 그룹을 재사용하고 두 번째 좌표에 원본 tool index를
사용한다. 도구 index가 역순으로 수신돼도 그룹 안에서는 원본 index순으로 표시된다.

```text
(0, -1) 추론
(1, -1) 본문
(2,  0) tool index 0
(2,  7) tool index 7
(3, -1) 다음 본문
```

기존 호환 확장의 annotation은 대상 본문 그룹의 하위 순번을 0부터 배정한다. 대상이 없으면
새 출현 그룹을 배정한다. 이는 OpenAI·vLLM의 공식 스트리밍 annotation 지원을 의미하지 않는다.

### Responses

| 정보 | 정규화된 좌표 |
|---|---|
| 위치 없는 단일 audio/transcript | `(0, -1, -1, -1)` |
| 일반 메시지 part | `(1, output_index, content_index, -1)` |
| part annotation·file_path | `(1, output_index, content_index, annotation_index)` |
| reasoning 요약 | `(1, output_index, 0, summary_index)` |
| reasoning 원문 | `(1, output_index, 1, content_index)` |
| 도구 호출·결과·기타 item | `(1, output_index, -1, -1)` |
| 응답 전체 인용 | `(2, citation_index, -1, -1)` |

서로 다른 종류의 item은 `output_index`가 구분하므로 같은 성분을 서로 다른 의미로 사용할 수
있다. annotation은 대상 part 다음, 다음 part 이전에 위치한다. 빈 reasoning item의 초기
메타데이터는 첫 실제 추론 part에 연결한다. 실제 part 없이 종료되면 별도 추론 블록으로 보존한다.

### GenerateContent

| 그룹 | 정보 | 두 번째 좌표 |
|---:|---|---|
| 0 | 입력 차단 정보 | 생략: `-1` |
| 1 | 본문·추론·도구·미디어·기타 part | 독립 part의 최초 출현 번호, 0부터 |
| 2 | candidate 인용 | 원본 `citationSources` 배열 위치 |
| 3 | grounding | 생략: `-1` |
| 4 | URL 조회 메타데이터 | 생략: `-1` |
| 5 | 안전 평가 | 생략: `-1` |

콘텐츠 part 사이의 출현 순서는 유지한다. 연속 텍스트·전사의 후속 조각은 기존 part 좌표를
재사용한다. 메타데이터는 수신 시점에 영향을 받지 않고 고정 그룹에 위치하며 같은 정보를 갱신한다.

## 4. 커스텀 변환은 정규화된 좌표를 확장한다

vocabulary 등 커스텀 변환은 정규화된 입력 좌표를 보존하고, 필요한 분류·조각 번호를 오른쪽에
추가한다. 분할한 블록의 후속 조각은 확장된 좌표도 재사용한다. 현재 cite 변환은 입력 좌표에
조각 번호 한 성분을 추가하며, 통과 블록에는 0을 추가한다.

```text
변환기 출력:
본문          (1, 2, 0, -1)
주석          (1, 2, 0,  0)

cite 변환 후:
본문 조각 0   (1, 2, 0, -1, 0)
본문 조각 1   (1, 2, 0, -1, 1)
기존 주석     (1, 2, 0,  0, 0)
```

본문 조각 전체가 기존 주석보다 먼저다. 커스텀 변환이 입력 블록과 그 하위 블록을 혼동하지
않도록 먼저 입력 길이를 정규화하는 이유다.

커스텀 변환의 확장 깊이를 1로 제한하지 않는다. 한 단계가 두 성분 이상을 추가해야 한다면
그 단계도 최대 추가 길이를 고정하고, 짧은 확장 부분을 `-1`로 정규화한 뒤 다음 단계에 제공한다.
다음 단계는 정규화된 전체 좌표 뒤에 자신의 좌표를 추가한다. 원본 본체를 별도 블록으로
유지하면서 하위 항목을 추가한다면 본체의 확장 부분은 `-1`, 실제 하위 번호는 0부터다.

`AnnotationBlock.target_seq` 등 참조 좌표도 해당 변환의 규칙에 맞춰 함께 변환해야 한다.
현재 cite 변환의 대상 참조는 대상 본문의 첫 조각인 `(*target_seq, 0)`을 사용한다.

## 5. 순서와 중복 처리를 구분한다

같은 seq는 같은 블록이라는 뜻이며, 같은 이벤트를 이미 처리했다는 뜻은 아니다. 문자열 델타를
재전송하면 별도 중복 제거가 없는 한 다시 누적된다. 완료 스냅샷과 델타의 구분, 이벤트 중복
제거, 같은 종류의 독립 블록 식별은 변환기가 해당 API의 정보로 처리해야 한다.

소비자는 전체 seq를 식별값으로 사용하고 사전식으로 비교한다. 벤더별 성분 의미를 해석하지
않는다. 최종 응답은 seq 순서로 index를 0부터 확정하고 seq를 제거해 저장한다.


## 6. 순위 계산과 응답 확정의 책임

`streaming/sequence.py`는 정수 좌표만 처리한다. `normalize_seq(seq, width)`는 길이를
정규화하고 `rank_seq(sequences)`는 입력 순서를 유지한 각 좌표의 순위를 반환한다.

```python
rank_seq([(20,), (5,), (10,)])  # [2, 0, 1]
rank_seq([(20,), (5,), (20,)])  # [1, 0, 1]
```

반환값의 i번째 원소는 입력의 i번째 seq에 대응하는 0 기반 순위다. 같은 seq는 같은 순위를
받고, 빈 입력에는 빈 목록을 반환한다. 입력 목록이나 모델 객체를 변경하지 않는다.

`models/hub.py`의 `finalize_response(response)`가 이 순위를 받아 실제 블록의 index 지정,
블록 순서 재배치, 주석의 target_seq → target_index 변환, 저장용 seq 필드 제거를 수행한다.
따라서 sequence 모듈은 HubResponse·ContentBlock·AnnotationBlock에 의존하지 않는다.
